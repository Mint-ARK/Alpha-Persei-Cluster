## 一、 项目概述与设计思路

本项目是一个针对游戏客户端的本地离线环境模拟尝试，主要包含以下设计考虑：

1. **本地离线沙盒**：
   网络交互、身份认证、资产结算、概率抽取与数据存储均在本地离线进行，默认网络通信集中在 `127.0.0.1` 环回网络或局域网内部。
2. **双进程托管方案**：
   桌面管理壳基于 WinUI 3 (C# / .NET 10) 构建，负责管理 Python 服务端子进程，利用 Windows 系统的作业对象 (Job Object) 机制在程序退出时自动回收底层进程，防止孤儿进程残留占用端口。
3. **渐进式迭代演进**：
   项目从早期的协议录制与重放逐步演进而来，目前接入了事件总线分发、动态 Protobuf 编解码处理与 SQLite 结构化存储，力求在脱机环境下尽量恢复常规游玩体验。

## 三、 快速上手与运行指南

### 3.1 运行前置条件

* **操作系统**：Windows 10 及以上系统（推荐 x64 架构），确保设备上可用 Microsoft Edge WebView2 和 WinUI 3 运行库；
* **环境依赖**：
  * **Python 3.10+**；
  * **.NET 10.0 Runtime / SDK**（若使用桌面启动壳）；
  * **Microsoft Edge WebView2 Runtime**（Windows 11 通常已预装）；
* **运行权限**：由于程序需修改系统 HOSTS 文件并监听 443、80 等特权网络端口，运行或安装时请使用管理员权限启动。

### 3.2 模式 A：桌面端运行 (推荐)

1. **启动桌面管理壳**：
   ```powershell
   cd LocalServer
   dotnet run -c Release
   ```
2. **安装本地根证书**：
   在桌面客户端界面中根据提示点击安装自签根证书（用于让客户端信任本地 HTTPS 认证连接）。
3. **一键启停托管**：
   在界面中点击 **“启动服务”**。桌面程序会自动检测端口状态、拉起底层 Python 服务并在内嵌 WebView2 视窗中呈现管理面板。

### 3.3 模式 B：纯命令行运行

适合无界面调试环境或直接运行 Python 核心：

1. **安装 Python 核心依赖**（*源码调试需要；若使用 Release 便携包或安装包，环境已内置封装，开箱即用，无需执行本步*）：
   ```powershell
   cd v5_server
   pip install -r requirements.txt
   ```
2. **安装根证书**（需管理员权限）：
   ```powershell
   ..\一键安装Windows证书.bat
   ```
3. **启动服务端主程序**：
   ```powershell
   python main.py
   ```
4. **访问管理面板**：
   在浏览器中打开控制台输出的地址（如 `http://127.0.0.1/web/gm_console.html`）。

### 3.4 客户端网络重定向方案

游戏客户端在启动和登录时会向官方域名发起资源与认证请求。在本地单机模式下，需要将这部分流量导向本地：

#### 方案 1：系统 HOSTS 静态解析 (推荐用于 Windows PC 客户端)
在 `C:\Windows\System32\drivers\etc\hosts` 中将对应域名解析指向 `127.0.0.1`。桌面启动壳提供了自动添加功能（出于安全与规范考量，此处不具体列出劫持域名）。

#### 方案 2：移动端真机 (iOS) 局域网协同
1. 确保手机与运行本服务端的电脑处于同一 Wi-Fi 局域网内；
2. 服务端通过指定参数启动（监听局域网 IP 并开启 DNS 辅助解析）：
   ```powershell
   python main.py --host-ip 192.168.1.100 --dns
   ```
3. 在手机 Wi-Fi 高级设置中，将 DNS 服务器手动指定为电脑的局域网 IP（如 `192.168.1.100`）；
4. iOS 设备使用 Safari 访问 `http://192.168.1.100/sdk_ca.mobileconfig` 下载并安装信任证书描述文件；
5. **说明**：由于作者手头测试设备有限，目前仅对 iOS 设备进行了初步连通测试，暂未对 Android 及 HarmonyOS 设备进行针对性验证。从原理解析上理论可行，但尚未经过完整验证。

## 四、 服务端启动参数说明 (CLI Arguments)

在 `v5_server` 目录下执行 `python main.py --help` 可查看完整的命令行参数说明：

| 参数选项 | 数据类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `--host-ip` | `string` | 自动检测 LAN IP | 指定绑定的局域网 IPv4 地址，用于向移动端下发远程连接地址 |
| `--https-port` | `int` | `443` | HTTPS 认证网关与 SDK 授权监听端口 (特权端口，需管理员权限) |
| `--gw-port` | `int` | `8102` | TCP Gateway 网关端口，客户端长连接首跳握手通道 |
| `--game-port` | `int` | `8105` | TCP Game 逻辑业务端口，承载游戏运行时大部分交互报文 |
| `--battle-port` | `int` | `6105` | UDP 战斗服务器端口；传入 `0` 时禁用独立战斗服 |
| `--db` | `string` | `account.db` | 指定使用的本地 SQLite 数据库路径或文件名 |
| `--res-version` | `enum` | `auto` | 客户端资源版本指定：`auto` (自动识别)、`229`、`311` |
| `--client-assets-dir` | `string` | 留空 | 指定游戏客户端 `StreamingAssets` 路径，用于辅助版本探测 |
| `--capture-cdn` | `flag` | `True` (开启) | 启用官方 CDN 资源反向请求与本地缓存保存功能 |
| `--no-capture-cdn` | `flag` | - | 关闭外部 CDN 请求，采用纯本地离线资源模式 |
| `--dns` | `flag` | `False` | 启动轻量级 UDP 53 端口 DNS 解析辅助服务 (需管理员权限) |
| `--log-level` | `enum` | `INFO` | 控制台日志输出级别：`DEBUG`, `INFO`, `WARN`, `ERROR` |
| `--self-check` | `flag` | - | 执行基础系统组件与操作类注册自检后安全退出 |

## 五、 服务端核心架构：模块职责明细 (共 70 个模块)

服务端源码按层次与职责进行了模块化拆分，`v5_server` 根目录下的 70 个 Python 模块按照实际代码逻辑划分为以下 9 个子系统：

### 5.1 服务端主装配与生命周期入口 (4 模块)

* **`main.py`**：系统主入口。负责命令行参数解析、运行环境与特权端口检测、装配核心调度组件并拉起多协议异步监听任务；
* **`login.py`**：登录流程编排。读取登录模板与本地数据库，负责玩家全量资产与状态的初次同步下发及会话初始化；
* **`server_daemon.py`**：独立后台守护进程辅助模块。提供基础 PID 管理、服务存活检测与安全停机钩子；
* **`replay.py`**：报文回放与协议重放调试脚本。支持从历史素材中加载序列化帧并模拟客户端发包行为（早期遗留模块，目前基本处于废弃状态，仅在特殊调试环境下使用）。

### 5.2 网络传输与多协议监听层 (6 模块)

* **`server_net.py`**：多协议网络接入层。监听 Gateway (8102) 与 Game (8105) 两个异步 TCP 端口，集成 HTTPS (443) 与 HTTP (80) 路由，并提供静态资源与 WebP 文件服务；
* **`transport.py`**：底层 TCP 传输帧封包与拆包。处理字节流粘包拆包、魔数校验、包体长度计算与序号解算；
* **`dns_server.py`**：轻量级 UDP 53 端口 DNS 辅助解析服务。用于移动端真机局域网接入时将特定域名解析至电脑局域网 IP；
* **`cdn_proxy.py`**：CDN 透明代理与本地缓存。从远程获取客户端请求的补丁文件并自动落盘到本地缓存目录；
* **`fetch_manifests.py`**：资源清单抓取与解析工具。探测远程更新清单并辅助建立本地文件版本索引；
* **`gen_cert.py`**：自签根证书（CA）与服务器 SSL 证书生成工具，支持导出适用于 iOS 设备的 `.mobileconfig` 证书描述文件。

### 5.3 会话调度与业务管线中枢 (5 模块)

* **`core.py`**：会话调度与业务请求分发。解析请求报文序列号（sn），组装 `OperationContext` 事务上下文并提供全局异常捕获；
* **`middleware.py`**：管线中间件。处理基础会话鉴权校验、心跳维活、基础骨架包补齐与下行帧队列调度；
* **`operations.py`**：操作命令集中注册与实现。定义了 130+ 个原生业务操作类，负责入参校验、业务数据落库与结果调度；
* **`event_bus.py`**：轻量级进程内发布-订阅（Pub/Sub）事件总线。解耦各业务服务间的直接调用，支持跨系统事件联动；
* **`protocol_ref.py`**：协议常数定义表。集中映射 1xxxx~9xxxx 协议号命令字与错误码语义。

### 5.4 动态 Protobuf 编解码与响应合成体系 (7 模块)

* **`codec.py`**：动态 Protobuf 二进制编解码驱动。支持在无需编译静态 proto 代码的前提下直接进行动态序列化与反序列化；
* **`generator.py`**：下行协议响应帧生成器。根据对应的数据结构装配登录同步帧、增量推送帧与通用业务回包；
* **`decode_schema.py`**：协议 Schema 反向推导与字段类型字典解析辅助；
* **`hero_codec.py`**：角色养成数据结构专属序列化辅助。处理技能树、神格星盘与跃迁等复杂嵌套结构的编解码；
* **`reserve_codec.py`**：阵容预设与备选配置编解码辅助模块；
* **`daily_fatigue_codec.py`**：每日定时免费体力补给（午间 11:00 与晚间 18:00 各 +30 体力）的领取状态管理与 `sc_12045` 报文构建；
* **`schema_default.py`**：协议字段缺省值推导与空值占位垫片，保障协议结构的向下兼容。

### 5.5 数据持久化与结构治理 (2 模块)

* **`account_db.py`**：本地 SQLite 数据库访问层。封装数据库连接管理、表结构初始化、事务提交与基础 CRUD 操作；
* **`normalize_db_transitions.py`**：角色跃迁技能数据清洗脚本。将数据库中 `hero` 表的 `exclusive_skill_list` 字段从旧版嵌套列表迁移规整为标准 JSON 格式。

### 5.6 核心业务领域服务集群 (25 模块)

1. **`hero_service.py`**：修正者角色养成服务。管理角色等级经验、突破进阶、技能加点、神格星盘装配与武器跃迁技能；
2. **`draw_service.py`**：抽卡与卡池服务。管理 4 大保底系列（精准90、精准70、常规70、钥从70）、概率抽取计算、大保底防歪判定、重复角色折算碎片与卡池动态下发；
3. **`inventory_service.py`**：道具与资产管理服务。统一管理货币、材料、碎片、刻印、钥从等资产的出入库与扣减，并生成原子变动帧（`sc_17023`）；
4. **`achievement_service.py`**：成就系统服务。监听全局业务事件推进 478 项成就进度，达成时下发金色成就横幅帧（`sc_53003`），支持成就物语与奖励领取；
5. **`fatigue_service.py`**：体力自然恢复服务。按 360 秒（6 分钟）恢复 1 点体力的节奏推算时间戳，并依据等级动态计算体力上限；
6. **`equip_service.py`**：刻印资产服务。支持刻印强化（多余经验材料返还）、阶位突破、词条洗炼赋能、神系同调重构、孔位装配与套装属性继承；
7. **`servant_service.py`**：钥从资产服务。以全局唯一 ID 独立管理钥从实例，支持钥从唤名（沉眠之殁转专属专武）、升阶精炼、加锁、上阵佩戴与分解出售；
8. **`chip_service.py`**：芯片领域服务。统筹弥弥尔管理喵芯片方案预设、角色专属 AI 行为倾向芯片（4 大职能槽位）以及助战战术芯片；
9. **`stage_service.py`**：关卡推进与章节服务。管理主线、支线、常驻活动、日常副本进度流转、三星条件评级与首通奖励，支持开荒与全通等预设模式；
10. **`mail_service.py`**：邮件与信件收藏室服务。管理收件箱、信件收藏室、多附件道具原子领取与角色生日信件阅读；
11. **`shop_service.py`**：商城与交易区服务。管理常驻代币商店、补给礼包、每日采购（Shop 2）商品加权抽取与主动刷新、日/周/月限购重置；
12. **`recharge_service.py`**：充值模拟与累充服务。支持商品识别发货、首充双倍模拟、累充积分计算与累充档位奖励领取；
13. **`trust_service.py`**：角色好感度服务。管理修正者好感等级（Lv.1~Lv.5）、送礼交互、出战心情倍率与专属关系网养成；

## 六、 WinUI 3 桌面宿主与看门狗 (`LocalServer`)

桌面端采用 **WinUI 3 + .NET 10** 构建，主要起到进程管理与内嵌展示作用：

* **作业对象进程托管 (Job Object Supervisor)**：
  * 基于 Win32 原生 `CreateJobObject` 与 `SetInformationJobObject`，配置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`；
  * 当桌面宿主程序退出（无论是正常关闭还是异常崩溃）时，操作系统内核会自动清理绑定的 Python 子进程，降低端口被孤儿进程占用的概率；同时 Python 服务端内部也具备启动时排查清理残留端口的保护逻辑。
* **内嵌 WebView2 视窗**：
  * 内嵌 Edge WebView2 组件，在服务端就绪后直接加载管理面板网页。
* **标准流重定向**：
  * 异步读取 Python 的 stdout 与 stderr，并在界面文本框中进行流式输出，方便观察运行动向。

## 八、 常见问题与排障说明 (Troubleshooting)

### 8.1 客户端提示网络连接失败 / 4xxxx 报错
* **排查方法**：
  1. 检查系统的 HOSTS 文件是否已正确写入重定向条目（需指向 `127.0.0.1`）；
  2. 确认 `AetherGazer V5 Root CA` 证书已正确导入至系统的“受信任的根证书颁发机构”中；
  3. 若设备开启了网络代理工具（如 Clash、v2ray 等），需将相关域名与 `127.0.0.1` 加入直连规则，防止本地回环流量被代理拦截。

### 8.2 提示端口已被占用 (WinError 10048)
* **排查方法**：
  * 检查 443、80 或 8105 等端口是否被其他本地 Web 服务器（如 IIS、Apache、Nginx、VMware 等）占用；
  * 可在终端运行 `netstat -ano | findstr :443` 查询占用该端口的进程 PID，并在任务管理器中结束对应程序；
  * 启动程序时必须使用**“管理员身份运行”**，否则无法正常监听特权端口。

### 8.3 客户端资源版本不匹配
* **排查方法**：
  * 确认服务端启动时指定的版本（`--res-version`）与客户端版本匹配（例如 229 版本客户端应配合 `--res-version 229` 运行）；
  * 系统内置了版本过滤规则，在 229 模式下会自动隔离 311 专有卡池与活动配置，防止客户端因找不到资源发生闪退。

### 8.4 证书信任失败 / 提示 SSL 握手异常
* **排查方法**：
  * 检查 `v5_server/sdk_ca.crt` 证书是否有效；
  * 在 Windows 运行窗口输入 `certmgr.msc`，检查“受信任的根证书颁发机构 -> 证书”下是否存在 `AetherGazer V5 Root CA`，若不存在可重新运行 `一键安装Windows证书.bat`。
