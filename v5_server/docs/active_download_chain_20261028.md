# 主动资源工具链

## 已实现的执行流

一份渠道、清单与范围配置是一条全局任务。调度器按加入顺序选择1–8条任务形成执行组，串行与并发使用同一流程。组内文件共享默认32、可调1–128的窗口，按成员轮询派发；修改任务并发数时等待在途文件结束后重组，不为每条任务另开一套窗口。

面板「主动下载设置」可单独设置总限速（MiB/s，填 0 为不限速）。所有主动任务共享一个上游资源正文读取额度，包含资产、语音和清单，保存后对在途下载的后续读取生效。按 KiB/s 存入本地下载设置，旧配置默认不限速。缓存命中、元数据探测与游戏客户端的被动下载不消耗额度；限速等待仍能响应取消和被动抢占。

入队时固定主清单快照及SHA256；任务开始取得主动执行权之后，索引管理器才扫描缓存。索引从主清单解析对象摘要/大小与延迟分组，以“渠道＋摘要文件名”为对象标识，合并多个任务的引用。有效缓存剔除，坏缓存列入修复；执行组向下载内核传入剩余对象，省去下载前重复存在性/整文件校验。对象锁、接收验证、磁盘回读摘要、备份与原子发布保留。

`runtime/cdn_downloads/verified_assets.json`保存通过校验的资产绝对路径和文件身份，包含设备、文件编号、大小及时间戳。下载过程中每约30秒有变化才保存，扫描或执行组结束时补存，写入采用临时文件和原子替换。恢复仍扫描当前目标目录，只有身份与大小匹配才跳过文件正文校验。首次使用、切换目录、文件变动或索引损坏时按实际文件重建，残片不进入索引。写入失败时队列继续工作并记录日志。

资产的必须范围为主清单中未列入 `assetPendDict.pendDict` 的路径，扩展范围取延后分组与主清单的交集。可附加中文、日语，或建立仅语音任务。语音对象由对应语种的 `voice_hash` 确定，必须和扩展按主清单的 `assetPendDict.allVoice` 划分，全部覆盖所选语种清单的所有对象。该范围用于服务器备份，客户端的分阶段下载还会应用自己的阶段规则。`assetPendDict.disable=true` 时扩展为空。资产分组缺少下载规格时单列；某条延后语音未收录于所选语种时，该语种没有对应对象。

“仅准备官方清单”可同时保存语音包总表和所选语种索引，确认后才请求缺失文件。同时选择中文和日语时，校验通过的完整清单组直接登记为可手动应用的原生分发方案。分发页也可通过“准备分发”补齐已保存主清单的语音索引。下载管理和分发页读取同一目录。资产与语音任务入队时固定所需清单快照，已登记的兼容方案使用其原生来源的语音索引。

## 被动优先与中断

`cdn_transfer_control.py`使用进程内条件变量、跨进程文件锁和持锁的被动等待标记。主动组独占传输会话，被动请求共享读取锁且不设全局并发上限。被动标记先发布，再等待主动让出；主动等待者看到标记不会先行。Windows使用真正共享的LockFileEx，Linux使用flock；标记进程退出后锁自动释放，遗留空标记不阻塞。

实际被动回源由`stream_upstream_and_cache`进入门控；已验证缓存的只读分发继续直接服务。被动到来时主动停止派发，主动关闭连接，等线程退出、残片回收后释放执行权。主动恢复重新建立缓存索引，复用已验证身份回执；被动补齐的文件不会重新下载。建立索引及发布前的摘要读取也支持取消检查。

连接中断覆盖TCP连接、TLS握手和正文接收。域名解析仍受原有DNS/DoH单次超时约束，不能把所有系统调用宣称为零延迟。任务关闭确认与门控释放均在工作线程真正退出之后。Windows残片进入系统回收站，Linux移动到同文件系统`.recycled-downloads/`，无物理删除；完整缓存保留。意外进程崩溃留下的残片不参与命中，未做自动永久清理。

## 任务与统计

状态包括排队、等待被动、建立索引、等待确认、下载中、暂停、取消、完成、有未解析引用、失败。分析任务不下载资产，恢复分析任务也不会自动获得下载授权。单任务可暂停/继续/取消/重试，排队任务可上下移动。取消单个共享对象订阅不会误停其他任务需要的传输；最后一个订阅退出才中断。

进度按已验证完整文件统计；接收速度按实际网络字节统计，含重试消耗。共享文件会同时推进多个任务，但流量只归实际接收任务，队列总速率不重复累加。当前执行组进度按唯一对象统计。速度为最近两秒窗口，短暂停止时数值会自然衰减。没有实现严格带宽均分或限速。

`runtime/cdn_downloads/queue.json`保存参数、状态及阶段性报告，`blueprints/`保存快照，`coordination/`保存锁。网络分块只更新内存统计，不逐块改写整份状态。重启后未完成任务暂停，完整文件是恢复依据；恢复时重新分析剩余对象，不进行未验证字节拼接。一个队列目录仅允许一个管理进程持有所有权。

报告可从任务行下载JSON，包含来源、摘要、范围、缓存/下载/失败统计。失败详情最多1000条、未解析路径最多200条，报告明确标注限制，计数保留全量。队列最多100条未结束任务、500条总记录，已结束记录可移除，不删除对应资产。

## Web与CLI

资源页增加HeroUI3主动下载区域，包含渠道、方案/已保存文件、必须/扩展/全部、分析和入队，以及总速度、文件窗口、并行任务数、执行组和单任务进度。官方检测保留完整appVersion/buildCode/安装包版本/文件名/渠道与差异，唯一下载入口为“前往下载管理”；缺失清单带入“仅准备官方主清单”，准备完成后可用该文件配置资产任务。

主要API：

| 接口 | 用途 |
| --- | --- |
| GET/POST `/api/gm/system/download_queue` | 状态/创建任务 |
| POST `download_queue/action` | 暂停、继续、确认下载、取消、重试、排序、移除记录 |
| POST `download_queue/settings` | 并行任务数1–8 |
| GET `download_queue/catalogue` | 当前渠道目录中的已保存主清单 |
| GET `download_queue/report/<id>` | 任务报告 |

旧`system/download_manifest`现返回任务ID与队列状态，实际准备步骤入队；旧`system/sync_update`同样转交全局队列，不自动改变分发选择或业务版本。内部旧UpdateTaskManager保留兼容回归，但整个调用受同一门控约束。所有公共对象下载入口默认受主动门控，索引快速通道要求持有有效执行会话。

```text
python tools/download_assets.py --platform pc --scope all
python tools/download_assets.py --platform ios --profile 方案短ID --scope extended --analyze
python tools/download_assets.py --platform pc --profile 方案短ID --voice zh --voice ja --scope all --analyze
python tools/download_assets.py --platform ios --profile 方案短ID --voice-only --voice ja
python tools/download_assets.py --standalone --platform android --manifest 完整清单名 --scope required
python tools/download_assets.py --platform ios --manifest 完整清单名 --manifest-only --voice zh --voice ja
```

默认CLI连接本机服务端；可用`--server-url`指定运行中的服务器。没有服务端时显式传`--standalone`，仍遵守全局所有权和跨进程门控；不要同时启动第二套管理器。`--workers`设置文件窗口1–128。Ctrl+C暂停本任务（独立模式暂停本地队列），不清理完整文件。旧PC/iOS脚本命令入口委托统一CLI；未保留旧的前N文件测试参数。
