## 本轮实现

新增summer_board_npc.py。85014按原生NPCManager倒序编号行动；一次回传npc_path_list{npc_id,path,move_num}，对应的85031事件先入客户端事件队列。服务端保存全部路线演算后的状态，重连85001恢复最终快照，不重播NPC回合，不追加在线全量图。

经过玩家按10113/10123扣1/2局内金币；踩中按10116/10126等实际NPC池传送并扣5/10，区域传送坐标从配置取。玩家踩中小/大鸭按10117/10127得10/20并移除；经过不冒充踩中。保护/无敌Buff先处理，再确认NPC仍存在才执行普通相遇。Buff效果计数、时长及嵌套事件保持原生参数。

两个NPC停在同格接10008：已有目标类型则保留其编号，否则分配新编号生成大鸭。新生成NPC不加入本回合初始行动集；已被前一NPC移除的后续NPC不进入路线表。map.next_npc_id单调递增，避免同回合删后新增复用编号；仅内部存储，85001只发送原生六字段，消除私有键编码警告。

随机停鸭机会和10012道具使用原生NPC属性12保存最多3个停止回合，每次玩家回合结束减1，重复使用刷新至至少3。停止和一开始无合法邻格的NPC不进入npc_path_list；恢复后按正常骰子行动。未给未行动NPC伪造Buff回合更新，与客户端没有OnMoveEnd的行为一致。

同时补属性读取下限：原生GetAttribute读取时受min限制，存储保持SubAttribute运算后的raw值。NPC经过40003触发25，骰子数可存0但应按至少1个读取，不能因此在下一回合拒绝服务。

物件fix_walkable=1现已由原生ChangeThingByExtentID确认会封路/移除占位NPC/传送占位玩家，加入共用相邻判断及物件变更投影。

## 原生消费者核对

- NPC_TURN_START/END timing11/12参数[actorID]；NPC相遇timing7/8/9参数[actorID]，玩家相遇timing6/10参数[targetNPCID]，Buff相遇timing21—24参数[effectID]。playerA/B按Lua匹配，不能只给空参数。
- 自动格不扣步，不执行普通格钩子；原生NPC只有path第一个点为普通格时触发开始移动钩子。
- NPC停止格是物件钩子存在有效npc_params时优先，否则地板钩子，原生是elseif；玩家仍保留两个独立钩子。
- OnPlayNPCDiceAni遇move_num<=0直接return，不会调用MoveCurNPCNextStep。因而不可用“空路径+0步”表示停止，否则本地回合卡住。
- NPC移动中被消灭/合成，客户端会跳过该实体后续步骤；路线的初始move_num仍保留原骰子点数，不能改成实际走过的普通格数。

## 路线选择口径与边界

客户端消费服务端显式路线，原C#分叉偏好尚未定位。本轮采用服务端规则：在合法邻格中优先不反向，候选等概率；只有死路才允许掉头。不是原服务器寻路算法还原声明。

自动格循环有重复状态及全回合512跳上限，沿用32层/512事件解释上限，无重试循环。开始完全被围住则跳过，中途被事件完全封死但仍有步数则整次失败回滚，不能下发让客户端还有剩余步数却无下一坐标的路线。NPC数量64及uint32单调序号为服务端保护上限；未发现原生数量上限配置。
