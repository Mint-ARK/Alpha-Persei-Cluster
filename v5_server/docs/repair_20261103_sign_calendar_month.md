# 控制面板签到日历跨月标记修复

用户在云端面板发现上月签到蓝点出现在本月同日，切到上月则没有蓝点。

## 原因与修改

- `GMReader.get_month_sign_days` 在当前年月无记录时取最新一行，但返回年月仍是当前年月。云端 account.db 实际为2026年10月的10、11、23、27、28日，旧HTTP接口却返回11月、累计5天。
- 查询改为读取记录自己的年、月，新增完整ISO日期 `signed_dates`；当月计数只统计年月相符的记录。非法日期、重复日、错误JSON和非整数项被过滤；非当月查询不再误报今日已签到。
- HeroUI v3 Calendar 按完整日期匹配蓝点，翻月不再用当前月过滤掉已有记录。非显示月份的格子样式使用组件的 `isOutsideMonth`，而非服务器当前月份。
- 撤掉无数据时默认点亮1—10日及“今日已签”的样例兜底。保留旧 `signed_days` 字段供原有月度统计使用。

仅修改只读DTO和界面，不改签到发奖/入库及游戏推流，不增加游戏帧。现有 `sign` 主键为 `(uid, activity_id)`，只保存该活动最新一个月；本票准确展示库中仍存在的年月，不新增历史归档，也不恢复已经被覆盖的月份。后台快捷签到的写入分支另有跨月沿用旧列表逻辑，本票未触及该写操作，留待独立修复。
