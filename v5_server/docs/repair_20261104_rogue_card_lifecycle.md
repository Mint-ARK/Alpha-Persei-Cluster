# 小游戏第一组：诡谈夜话对局、退出与恢复

日期：2026-11-04。证据及源码写前副本：`archive/minigame_roguecard_20261104/`。

## 修复内容

新增 `rogue_card_service.py` 管理服务端的对局生命周期，客户端仍负责卡牌局内规则。小游戏中枢保留显式方法入口，移除旧的空剧情处理和共用缓存实现。其他小游戏保留原行为；数据库绑定服务不再被另一个存档调用修改。

对照 `roguecardgameaction.lua`、`roguecardgamedata.lua`、`roguecardgamebridge.lua` 及论坛/挑战界面修正了请求含义：

| 请求 | 实际职责 | 修正 |
| --- | --- | --- |
| 89620 | 保存局内进度 | 验证对局 ID、模式、关卡及挑战参数，主线/挑战分别保存 |
| 89622 | 继续对局 | 返回对应模式的真实快照及可选回滚点，不把另一模式的内容套上请求 ID |
| 89624 | 中断结算 | 返回客户端读取的 settle_info，关闭本模式对局；不再误作复制回滚点 |
| 89626 | 写入回滚点 | 校验归属并仅保存主线的回滚点，保持与当前进度分离 |
| 89628 | 只读当前存档 | 读取对应模式，不产生中断或覆盖行为 |

- 开始/重开根据真实帖子配置检查前置，进入关卡检查与当前调查的对应关系。挑战牌组和难度使用客户端 ConditionCfg 的 12701/12702 规则及逐级条件。
- 主线与挑战各有对局身份和快照，旧 ID、错误模式、错误关卡不能污染当前记录。随机正整数 ID 限于 SQLite 可表示且协议 uint64 可容纳的范围。
- 正常调查先进入局内，再完成通关、后置剧情确认；纯剧情帖 107 不再依赖一个不存在的卡牌战斗才能完成。重复完成不重复广播完成任务。
- 中断不增加挑战通关难度；成功结算只记录当前牌组/难度。重复结算及重复中断返回已有结果，不重推整帧或任务差量。
- 点赞与 Lua 的本地切换回调一致，支持取消点赞；不在 ACK 前再推同一份点赞全量，避免本地回调把状态再次反转。
- 状态变更、现有帖子完成任务、必要响应准备在同一事务内。写后异常、必要状态包或 ACK 编码失败会回滚并可重试。
- 结算/快照中即将进入图鉴的物品 ID 使用当前配置目录校验，拒绝不存在的 ID 进入客户端查表链。

配置由 `tools/export_rogue_card_cfg.py` 提取，保存为 `rogue_card_cfg.json`：27 帖子、7 关卡、4 牌组、6 难度、77 卡牌物件、13 强化、25 机缘劫厄及3个牌组解锁条件。八份原 Lua SHA256 同时记录，发行包沿既有根目录 Python/JSON 收集规则纳入。

## 持久化与推送

沿用已有 `rogue_card_game_record` 的完成、点赞、浏览、收集和挑战历史；各模式运行身份、快照及重放回执放在本存档 `server_global_config` 的 `roguecard.runtime_v1.<uid>`。没有修改表结构。旧扁平快照只在关卡类型吻合时采用，不把主线快照复制给挑战。

当前模式没有独立进度差量协议：需要刷新调查/挑战状态时，在 ACK 前发一份 89601；保存和继续沿原回执携带快照，普通点赞由 Lua 回调更新；重复完成不再发冗余 89601。帖子完成仍走 `ROGUE_CARD_POST_FINISH → task_listener → 28007` 原子差量，没有新增任务全量。
