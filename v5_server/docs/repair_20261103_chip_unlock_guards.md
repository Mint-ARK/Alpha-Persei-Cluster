# A68/A69：角色AI与助战芯片解锁条件

依据health_audit_20260922_round44_reviser_unlock.md、round45_hero_chip_unlock.md、当前ChipCfg/ConditionCfg/GameLevelSetting、support/p08support.lua的IsConditionAchieved及HeroTools、ArchiveData、ChipTools消费路径。

## 修复

- A69：统一入口按原生目录存在性和type_id分派，不再用数值区间/尾号猜类别，不允许未知ID免费创建。角色AI直接入口也检查type3；宿主必须存在且已解锁，按new_condition核对等级，配置明确无费用才免费。完整费用按当前Lua汇总，全部余额先检查，之后由Inventory扣减。缺配置/材料不足不创建或解锁，已解锁重复请求不再扣费/发布首次事件。
- A68：助战入口必须通过养成与前置校验，移除“允许宽松放行”。基础type4/role5的spec_char是真实角色；扩展role6的spec_char是基础芯片ID，借此读取宿主，不能做CID除100推测。顺序直接来自ChipCfg的get_id_list_by_spec_char原生索引，必须先解锁当前序列的前一项。
- 动作与服务端红点复用同一守卫；红点保持原有“仅返回已有未解锁记录中可解锁项”的接口，跳过不在目录内的旧异常记录。未满足等级/星级/档案好感/属性强化的请求返回失败，不写解锁/不广播成功。
- 成功写入完整原生类别/角色/槽位等字段；合法目录目标即使原来没有静态行，也能按条件创建正确行。既有已解锁记录不批量迁移，不重扣费用。继续复用A71的首次事件、计数对账与50003事务准备。

## 原生条件与配置

新增chip_unlock_cfg.json与可重复导出工具，收录469项原生芯片、208个被AI/助战引用的条件、15条助战基础/扩展序列和好感经验曲线。配置覆盖需要备份目录，release_contract要求发行包携带新目录；不读取decompiled Lua作为运行依赖。

本项目没有可直接复用的通用IsConditionAchieved服务，本轮只实现当前两类解锁实际用到的4种条件，不伪造完整全局条件引擎：

- 1015：指定角色等级。
- 1026：指定角色原始star数值（如SS=400、SSS=500）。
- 1025：HeroTools.CountHeroTotalSkillAttrLv对应skill_intensify五种属性的等级总和，拒绝损坏/重复索引等异常数据。
- 1027：角色本体档案的好感等级。通过已有ArchiveService匹配本体，读取hero_archive.exp，用GameLevelSetting.hero_love_exp判定；不是交心trust_level。当前5级门槛为1000经验。

等级/星级/好感阈值均来自导出条件，扩展顺序来自引用索引；未知条件或缺少配置不放行。管理喵/普通次级类别也经过原生ID目录分派，但其原有独立解锁条件未在本票扩展认证。基线为当前Lua，未另认证其他旧版本的条件差异。

## 旧静态字段缺失兼容

旧合法资产可能unlocked=1但type/spec_char/slot字段为0。新目录已提供权威分类，因此A67装配及A71计数改为：拥有/解锁及账号归属由数据库提供，是否为当前合法芯片及类别/角色/槽位由原生目录提供。目录外或持久类别不匹配的行仍不计为对应资产，缺少整个目录则拒绝数量核对。

这覆盖合法旧元数据缺失，不需要直接覆写真实存档；也不因字段为0把真实拥有数量算少。A71上一票关于依赖DB静态type字段的实现由本节后续修正替代，已领记录保留策略与领奖资产复核保持不变。
