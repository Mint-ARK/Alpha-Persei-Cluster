# A62：共享保底与卡池独立自选

依据 `health_audit_20260922_round35_draw_inheritance.md`，承接A61查到的兼容快照字段不匹配，复核当前DrawService、16016/16017、16015、16018/16019及客户端DrawAction/DrawData。

## 修复

- `save_draw_state` 只把抽数和大小保底同步到当前池兼容快照，不再把系列 `up_id` 写回该池。新快照的 `up_id` 为0，已有选择（包含明确清为0）保持，只有 `set_pool_up` 修改它。
- 兼容快照按原生 `draw_state` 的真实列写入，去掉不存在的 `since_sr`；该计数继续由权威 `draw_group_state` 保存。不改数据库表结构，也不依赖为旧表补列。曾手工多加该列的库同样不再发生目标覆盖。
- 系列与池快照在保存点中一同成功或撤销，不再吞掉快照写入失败。显式选池的目标写入和系列状态保存同样有保存点，直接服务调用或外层事务中捕获异常都不会留下半份变更。
- 角色自选保持原来的按池读取；沉睡之子自选改为使用当前池的 `target_up`，不再读取系列最后选择。系列 `up_id` 列仅保留旧数据兼容，不用于跨池决定目标。
- `DrawSetPollUpOp` 必要16017响应在提交前准备，空响应不再冒充成功；写入/回包失败时，恢复原选择与共享进度。

原共享抽数、大小保底和系列隔离不变，GM垫抽仍只改进度；固定UP池继续忽略旧自选数据。没有从系列旧值猜测或补写历史选择，已存在的各池选择保留。

## 协议与Lua

DrawAction发送16016时由 `ConvertUpId(...,0)` 把界面展示选项转为配置目标，收到成功16017后客户端以原请求更新本池 `SetPollUpID`，因此无需额外推送整张16015。失败回执不执行该本地更新。

冷读取16015按池返回原始目标ID，客户端再由 `ConvertUpId(...,1)` 转展示选项；16019仍使用正确的DrawItemCfg条目ID，实际抽取使用同池目标。内部检查覆盖这三处数据的一致性，不改客户端Lua、不增加全量刷新。本票未改变钥从实例创建、UID和精炼等级生命周期。
