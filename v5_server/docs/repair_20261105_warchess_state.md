## 验收结论与范围

原生常驻入口 `ChapterClientCfg[404]`，名称“因果观测”，跳转 `/warChessStage`。配置中的第一张地图是 `4040101`，实际 UI 名称“斯皮尔特·组装线”；`WarchessLevelCfg` 内部名“工厂_1”不是 UI 标题。

该地图完整自然路线已通过内存 AccountDB、实际 Core、原生 codec：进入 → 逐格合法移动 → 路牌/机关/陷阱/事件 → 14 场原生战斗 → 战后地块转换与圣物选择 → 3 小箱、2 大箱 → 100% 探索 → 任务 → 退出 → 登录恢复与再进入防重。14 场均使用实际 `54030/54032`，没有手动把角色坐标移到每个箱子上代替路线验收。

首图箱子真实收益合计为 `1×400、2×5500、40801×6、40802×12、40803×4`。原实现的小箱固定“50 晶石+5000金币”、大箱固定“100晶石+5000金币”已移除。

**这是首图完整链路与共用基础的源码验收，不是 40 张地图全量完成，不是游戏实机验收。** 后续高级地图范围见下文，不因引擎已导入地图就宣称可通关。

## 实现

新增 `warchess_contract.json`、`warchess_service.py`、`warchess_battle.py`、契约导出脚本与两个专项验证脚本。

1. 六个原有 Operation（49002/04/06/08/16/24）改为同一明确的派发层，全部 `prepare_response_in_transaction=True`。无数据库、未知地图、越界/远程交互、伪造选择或未实现语义返回错误，禁止空成功掩盖失败。
2. `ops_common(kind=warchess_runtime_v2,item_id=active)` 保存本局 run、原生地图状态、事件队列剩余项、候选与战斗身份；地图/概要继续镜像原 warchess 表，无 DDL。状态逐次从账号数据库读取，无跨账号全局缓存。
3. 使用原生六向相邻规则与地块 `move/interact`，整条路径校验；陷阱按客户端时机停止移动，不提前移动到余下路径终点。`tag/state/rotation` 分开维护。客户端本地执行回调，因此成功 ACK 后不额外整张地图覆盖或再播一次事件。
4. 战斗事件 10201 先暂停队列，胜利才执行其余事件、替换怪物地块；失败保留怪物并更新尝试 token。只有后续真实 10202 地块交互才产生 `49011`，持久三候选，重连/重复请求不重抽；选择必须符合坐标、tag 和已发候选。10205 按配置直接添加负面效果，10206 按实际负面效果净化，不给普通圣物假删除权限。
5. 10203/10204 只按当前原生事件引用 DropCfg 发奖。唯一开启凭证与箱数累加在同一事务；数据库方法按 `rowcount` 防止重复累加；先占领取凭证再发奖，任何库存/必要帧失败全部回滚。资产 `17023`、任务 `28007` 均在 `49007` 前。
6. 任务 460/462/463 从持久箱数/地图进度投影，不依赖孤立战斗当作整图通关；已领奖任务不回写。对无指定地图的 462，目前用已达成阈值的不同地图作为可证明下界，不凭重复退出次数增加“通关次数”。463 为 100% 地图数。
7. `49008` 清本局状态与当前章节，保留永久箱子凭证；再入按原生地图重建，已领箱子正确投影为配置指定的扩展地块。首次迁入新引擎时，旧 `warchess_session` 原行先完整留存在 `ops_common(...,item_id=legacy:<chapter>)`，再建新局。旧实现混淆过 tag/state、假授圣物，不推断这些旧字段已经完成哪一个真实事件。既有永久箱数、已发资产不回扣。
8. 登录 `49001/49023` 强制按账号生成、去重补缺，在 10201 前发送；动态失败不回放录制数据。49001 按原生 `WarchessLevelCfg.type` 分组，活动章节不再全部塞进 activity_id=0。`gen_sc_49003` 改为读取已获授权的当前局，不再绕过 Operation 创建地图。

## 共享战斗接线

`warchess_battle` 导出：

| 接口 | 合同 |
| --- | --- |
| `reserved(kind,stage)` | type15 或原生288战斗ID由此族认领，阻止换类型绕过 |
| `entry(ctx,uid,info)` | 校验type15、次数1、原生stage、活动组、当前pending、编队与存量HP；index必须是 `z*width+x+1` |
| `publication(ctx,uid,bid,context)` | 必要入场帧准备成功后，在事务内绑定run/token/bid；新尝试替代旧尝试 |
| `validate(db,uid,session,after=False)` | uid/run/token/bid匹配；回执只在当前地图动作未再推进时重放 |
| `settle(ctx,uid,session,result,report)` | 独立结算，返回已编码必要帧；不走主线首通、经验、体力/掉落支路 |

`middleware` 保存 `warchess_context`；54032 对旧局、旧尝试、已推进地图后的旧回执直接拒绝。必要 54033 与 SQL 在同一保存点准备，失败不缓存成功 `br`。实际角色战报存在时按每角色 `hero_blood / hero_max_blood` 转为 0..10000；名单不匹配或非法数值失败。缺失角色战报保持已知记录，不从总伤害猜各角色 HP，不宣称完整战后血量已证明。
