# 共享资源存储位置

资源分发页右上角新增HeroUI3“资源存储位置”窗口。浏览、输入和保存的均为服务器路径，与查看Web面板的机器无关。可浏览磁盘/挂载位置、进入子目录、返回上级，或手填一个尚未创建的目录；保存时创建根目录和pc/android/ios三个子目录，分别检查可写性。目录列表最多200个子目录，扫描最多20000个入口，过大时提示直接输入完整路径。中文和空格使用JSON参数与UTF8处理。

## 目录与配置规则

- Windows无明确选择时优先推荐可写D盘；其次按可用空间推荐其他非系统固定盘，不自动选C盘。没有合适盘时保持未配置，允许用户主动选择C盘。旧模板的`./cdn_cache`且无选择标记视作出厂默认，其已有资源保留读取。
- Linux默认程序目录下cdn_cache，可用同一个Web窗口选择/mnt等实际挂载目录；操作使用服务进程权限。Windows盘符接口只在Windows分支调用。
- 明确配置的自定义根目录保留。自动推荐位置可原样点击保存固定，保存写入`storage.cdn_cache_dir`与`cdn_root_selected=true`。
- 旧根目录记入`storage.cdn_read_roots`，按平台读取；原D:\PC_DATA、D:\iOS_DATA、D:\Android_DATA继续作为兼容只读来源。没有搬迁、复制整库资源或删除旧文件。
- 明确目标不可写时报告错误，不再悄悄把新下载重定向到static_resources或其他磁盘。
- `CDN_CACHE_DIR`或平台环境变量仍是显式覆盖；Web显示覆盖状态并禁止配置一个不会生效的目录。

共享配置默认为服务端目录server_config.json。可通过`AETHERGAZER_SERVER_CONFIG`显式指定，两端相对路径均按服务端目录解析。启动壳的存储设置不再被另一份LocalAppData配置覆盖；壳生命周期等原有独立设置不在本轮合并范围。

保存仅合并相关字段，不整份丢弃未知字段。Python与C#使用同一路径的server_config.json.lock字节锁，读取最新内容后合并；原文件先留before_publish副本，再原子替换。残片及旧文件不物理删除。写权限检查会新建1字节的`.cdn-write-test-*`标记并保留，验证的是新建文件权限，避免“已有文件可改、目录不允许新增”时误报成功；索引忽略这些标记。

## 运行时切换

传输门控增加独占维护边界：主动下载、索引或被动回源在进行时拒绝切换，提示暂停并等待在途结束。切换后，下次开始下载会按当前目标目录重新建立索引，下载该目录中缺失或校验失败的资源。旧根目录仍可用于向客户端分发已有资源。

根目录在传输权限取得后解析，避免等待期间切换后仍写旧位置。每个主动组/被动接收会话获取权限时检查配置身份；有变化才重读JSON。索引文件循环没有逐个重读配置。独立CLI也会在下个会话同步其他进程保存的配置。

启动壳离线保存会建立平台目录并保留历史根；检测到运行中的源码服或壳进程服时，目录修改走同一个管理API和门控。接口不可达、配置身份不符或目录忙时报告错误，避免伪装成功。
