# A85/A87 梦境统一周期、旧档采用与原子刷新

2026-11-04。对照第60/62轮、当前AccountDB、weekly、LazyTimer与EventBus，统一梦境周四05:00周期。仅开发源码与内存测试，不直接迁移真实账号文件。

## 变化

- 新boss_challenge_cycle.py只负责显式东八区的周四周期起止、每日05:00起点及兼容种子算法。梦境下次刷新、持久水位、列表种子及周四广播使用同一时钟，Linux宿主时区不影响梦境边界。其他玩法的旧周期函数、周一/月/全局每日事件暂不扩大修改。
- 首领种子由boss_challenge_progress.cycle_id提供，不再每次读取按物理时间跳变。新周期只在周四起点计算一次兼容种子编号，因此旧周三06:13:20不再换首领。
- 旧档首次采用，在同一周内保留旧算法此刻展示的种子、成绩、英雄引用、领奖记录和模式，冻结到下次周四。server_global_config使用boss_challenge.cycle_clock_v1.<uid>标记已采用，种子与标记同事务写入；读取标记异常不能被当成“首次采用”。不需要改表结构。
- AccountDB.check_and_lazy_refresh_boss_challenge作为唯一刷新服务：成绩、锁定队、领史、兑换次数和模块水位在保存点事务中一起更新，任一步失败撤销整次清理；嵌套外层事务时，调用方捕获异常仍不会留下半次清理。
- 周四/每日BUS监听器均委托同一服务，以模块水位判断是否已完成。惰性读取先刷新、BUS先刷新、同周期重放均不会再次清掉玩家新成绩；每日仅清挑战次数，保留周进度，时间回拨不降低已有水位。
- 当前db_schema和AccountDB早已定义boss_challenge_exchange，旧报告的“标准新库缺表”不再适用。现有表的兑换次数统一清理；为缺少该表的历史结构，仅对这一个明确可选表做存在性兼容，不吞其他清理异常。
