## 契约和计分决策

原生第四章包含5310203/04/05/06四战，之前三章全部完成才解锁。HodurTemplate区分本轮分数、各首领历史最高分和历次挑战最高总分；last_status用于重打前的队伍血量。89424成功回调会缓存本轮结果并在本地ResetData，因此结束挑战不应额外发送清空状态的89421覆盖客户端缓存。

客户端说明给出时间、受击、连击、机制消耗四个评分维度，但Lua和战报没有服务端公式。只读核对PC229地图Blackboard及记录名映射，未建立可靠的连击/机制计数ID。用户明确授权先按奖励条件匹配私服计分，不把不透明原公式当成已还原。

配置门槛：400002为10万/30万/80万分，400003为携带2/4/6自限模块完成四战。私服v1按每战保底20万（四项各5万）设计，完整四战保底80万；正耗时在300秒内按剩余比例给时间项最多5万加分，受击在20次内按剩余比例给受击项最多5万加分。未识别的连击/机制维度给中性基础分，不把QTE或其他记录冒充这两个统计。最终单战分乘原生倍率`(100+所选词缀point总和)/100`，向下取整。清档门槛由任务配置最大分数导出。

9项词缀的point直接来自PublicBuffCfg→ActivityAffixPoolCfg，分别10/10/10/10/10/15/15/20/60。自限数量任务必须四战全胜，单纯开局选择或中途放弃不算完成。

## 血量比例的额外核对

x86/x64反编译Lua把GetChapterHeroHP返回值和百万精度临时变量混用，表面上容易误读成固定以1000000为分母。读取本机缓存原始scripts64（MD5 86add1e9d150efa2464ec96f0579a0b9）中的BattleController字节码，只读反汇编确认：CALL后先把HP与上限移入独立寄存器、DIVVV求比例，再乘/除1000000做精度处理。因此保持原始HP/上限是正确的，不应无条件把普通血量当百万比例值。原始字节码、汇编及地图证据仅放archive，不发布到运行包。
