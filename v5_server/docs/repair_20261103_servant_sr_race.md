# 四星钥从按当前自选神系产出

这是A62检查时发现的补充问题，不新增A编号，也不改变386条历史发现的统计。

## 依据与修改

客户端 `DrawPoolCfg[10002]` 明确说明四星钥从属于当前选择的神系，并通过 `optional_lists` 和 `optional_lists_a` 配对六位沉睡之子与各自两位四星钥从。旧DrawService在SR分支从全量12位四星中随机，详情16019也列出全部12位，与当前选择不符。

新增与该原生配置一致的六组明确映射，不按ID尾号猜测。四星产出使用当前池目标对应的两位候选，沿用原 `random.choice`；详情的 `a_other_item` 同步只列这两位的DrawItemCfg条目ID。映射也按原生4020201联动池的两条四星配置核对，两个联动目标归一化后均对应原生2450001/2450002；不据此宣称重构或验证了联动五星发奖规则。

保持原SR触发概率、共享计数、扣券、返利、SSR和三星产物规则。未选择时保留原候选兜底；不扩大本票为未选择/非法目标的前置资格校验。

详情继续用原 `a_other_item` 字段，不往 `a_up_item` 塞两位钥从。Lua `drawinfopopview.lua` 逐项遍历四星列表可处理两项，而其他角色描述分支直接取三位A角色，不适合挪用。新增候选不会把原生物品ID误当DrawItemCfg条目ID。
