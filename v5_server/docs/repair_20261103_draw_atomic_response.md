# A61：抽卡结算与必要回包同事务

依据 `health_audit_20260921_round34_draw_settlement.md`，复核当前DrawService、DrawOp、Core和客户端DrawAction。旧报告的库存异常吞掉路径已经不在当前源码；当前真实Core上，发奖抛异常会回滚，本票保留此正向对照并补齐提交后响应失败的漏洞。

## 修复

- DrawOp开启 `prepare_response_in_transaction`，扣券、角色/钥从/碎片/返利、系列保底、历史及必要回包准备成功后才提交。
- 16011编码为空时不再用 `08 00` 冒充成功。空值/异常返回Core既有非零结果，并撤销数据库及本次待发通知。
- 资产刷新使用 `_refresh_frames(strict=True)`。原17023等必要刷新出错不再被吞；角色帧异常会向外传播。
- 抽到钥从时保留原46011刷新路径，但生成失败或为空不能仅记警告后提交；失败会撤销新实例及抽卡消耗。
- `draw_record` 写入或保留100条的整理失败，不再吞错继续成功，交当前抽卡事务回滚。权威 `draw_group_state` 写入失败原本即会传播，本票以故障注入确认。

保持原概率、保底阈值、返利、正常成功帧顺序及实例生命周期。本票不增加全量刷新；原16011、17023、角色14007与钥从46011均保留，后者是否可完全交由实例差量替代仍属于A63。客户端DrawAction仅在16011.result=0时推进池状态与成功统计，非零回执仍走正常回调，不发送空成功结果。

## 验证

`tools/verify_draw_atomic_response.py`：8专项＋9角色获取回归＋10原子/概率回归，共27项通过，真实内存AccountDB/Core/DrawService/Inventory/codec。包含空/异常16011、空17023、角色帧异常、空钥从列表、库存首次与写后失败、权威保底及历史插入/整理失败，核对角色/实例/碎片/券/进度/历史及待发通知回滚；失败重试只扣一张券、写一条记录；正常单抽/十连、原70/90阈值保持。

旧DrawOp响应及DrawService相关方法提取对照：8组中的5组失败，共9次失败断言（含子用例及失败后状态已经改变的后续断言），不是9个独立BUG。当前库存异常传播与权威保底写失败在旧方法下已经正确，不归为本票新增修复。

证据位于 `archive/draw_atomic_response_20261103`。本票覆盖游戏操作事务，不把直接调用DrawService.draw当成自动创建事务的公共API；没有新增内部自动重试。Core已有边界不包含任意Python或外部副作用，事务内数据库消费者和待发送通知按当前检查点恢复，不声称任意外部回调可撤销。

## A62前置发现

本机发布schema及云端account.db的 `draw_state` 都没有 `since_sr`。旧 `save_draw_state` 却尝试写该列，兼容快照一直吞错跳过；真正的系列计数仍由 `draw_group_state` 保存。最初试图把该兼容快照也变为必需写入，27项中的正常抽取因该列缺失失败，检查捕获后撤回此范围，原输出保留。

下一票须把列合同和A62池独立UP一并处理：若仅修字段使快照写入恢复，会让原有“系列up_id覆盖本池选择”的潜在问题变成实际问题。不能单独加列或删字段后就忽略目标隔离。本票未改表、未关闭A62；其兼容快照仍是原有容错处理。
