# 第109轮｜BS战斗结果反馈与在线成长

扫描日期：2026-10-09。问题编号：A157、A158、A159、A160、A161、A162、A163。

## A157｜战斗成长依赖的表和列缺失，部分成长被跳过

### 出现什么现象

基础数据库中部分战斗成长静默不生效。

### 初步定位

初始化与迁移缺少 battle_win_times 字段和 user_behavior_stat 表，战斗监听在先加熟练度后因缺结构退出，其余成长被跳过。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `account_db.py` | init_schema、_COLUMN_MIGRATIONS |
| `hero_service.py` | 战斗成长 |

## A158｜战斗经验增加却不换算角色等级，突破上限也未限制

### 出现什么现象

战斗增加角色总经验却不提升等级，也可能超过当前突破经验上限。

### 初步定位

成长逻辑只累加 exp，没有复用等级曲线和突破封顶规则；角色编码仅回传现有字段，不负责重新计算等级。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `hero_service.py` | 战斗经验增长 |
| `hero_codec.py` | 角色字段 |
| `herobreakcfg.lua` | 突破上限 |

## A159｜账号等级经验曲线与客户端不同，等级和升级事件偏差

### 出现什么现象

相同账号经验在服务端和客户端算出不同等级。

### 初步定位

user_level_setting.json 的前段经验曲线与当前客户端错位；总经验20时服务端算三级，客户端按当前曲线算四级。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `inventory_service.py` | calc_player_level |
| `user_level_setting.json` | 账号曲线 |
| `gamelevelsetting.lua` | 客户端曲线 |

## A160｜战斗熟练度广播串入交互任务，未交互也增加进度

### 出现什么现象

只完成战斗也会推进“与修正者交互”任务。

### 初步定位

熟练度变化发出 HERO_UPGRADE，但任务监听不区分 oper，把 proficiency_up 也用于条件8，误推进6013。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `hero_service.py` | proficiency_up事件 |
| `task_listener.py` | on_hero_upgrade |
| `assignmentcfg.lua` | 6013 |

## A161｜战斗后交心心情已增加，在线客户端没有刷新

### 出现什么现象

战斗胜场已改变交心心情，在线角色状态却没有同步。

### 初步定位

TRUST_MOOD_CHANGE 只有生产者，没有业务消费者；普通结算没有携带更新后的 trust，完整角色恢复才显示新心情。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `trust_service.py` | 胜场与心情 |
| `event_bus.py` | TRUST_MOOD_CHANGE |

## A162｜扫荡未传递队伍和连携信息，编队与成长统计丢失

### 出现什么现象

扫荡后的队伍类型和连携统计与请求不一致。

### 初步定位

h_54038解析了类型、连携和弥弥尔，却未传给结算，也没有对应战斗会话；广播因此使用默认类型0和空连携。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `middleware.py` | h_54038、_settle_frames |
| `team_server.py` | 队伍记录 |
| `cooperation_skill_server.py` | 连携统计 |

## A163｜战斗成长只保存一部分仍返回成功，同场重试不补缺项

### 出现什么现象

战斗成长中途写入失败，仍回复结算成功；重试也不会补齐缺失成长。

### 初步定位

熟练度、胜场等已分别写入，后续异常在监听中被吞掉；结算成功缓存不检查关键成长是否全部完成，留下部分成功状态。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `hero_service.py` | 战斗成长监听 |
| `middleware.py` | 结算与缓存 |
| `core.py` | 事务范围 |
