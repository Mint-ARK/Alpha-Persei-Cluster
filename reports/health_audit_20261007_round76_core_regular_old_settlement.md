# 第76轮｜常规旧结算与成绩广播

扫描日期：2026-10-07。问题编号：A104、A105、A106。

## A104｜迭代校验旧战斗写入新轮次，影响新周期成绩和领奖

### 出现什么现象

迭代旧战斗跨周结算后，会给新一轮写成绩并开放对应任务。

### 初步定位

结算使用当前 cycle 选择和写入关卡，没有验证旧会话的 infoID 是否属于该周期，也未按开战时间拒绝跨期结果。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `middleware.py` | 常规迭代结算 |
| `account_db.py` | 迭代成绩写入 |
| `battlecoreverificationtemplate.lua` | GetDest |

## A105｜重复结算请求返回旧缓存，客户端成绩与次数回退

### 出现什么现象

同一战斗重复请求虽不重复记账，却返回旧周状态或旧图鉴计数。

### 初步定位

战斗缓存同时保存业务结果与当时的动态状态包，重试时原样回发 extra，没有重新生成依赖当前周期和计数的部分。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `middleware.py` | h_54032 的 result_data、extra 缓存 |

## A106｜迭代校验成绩刷新包结构错误，分数编码为空

### 出现什么现象

迭代成绩刷新包编码为空，客户端收不到正确分数。

### 初步定位

75015 需要 id 和 score，结算却把 max_score_info 的 lock_list 容器直接交给编码器，字段结构不匹配。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `middleware.py` | 75015 组装 |
| `lua_proto_messages.json` | sc_75015 |
| `p75_pb.lua` | 字段定义 |
