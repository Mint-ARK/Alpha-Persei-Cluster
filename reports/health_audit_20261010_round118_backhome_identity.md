# 第118轮｜后宅食堂冷初始化、岗位派遣身份与广播

扫描日期：2026-10-10。问题编号：A195、A196、A197、A198、A199。

## A195｜食堂更换岗位未移除旧岗位，同一角色同时占两岗

### 出现什么现象

同一角色或同本体的两个形态可以同时占两个食堂岗位。

### 初步定位

岗位写入只按岗位类型替换目标行，没有迁走该本体的旧岗位；恢复仍返回双行，而客户端本体只有一个 jobType。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | 岗位安排 |
| `account_db.py` | career写入 |
| `dormdatatemplate.lua` | jobType |

## A196｜食堂撤岗后 NPC 仅在线恢复，重登岗位信息丢失

### 出现什么现象

撤下普通员工后，在线自动补上的NPC重登后没有岗位。

### 初步定位

请求以 hero_id0撤岗，客户端成功回调按岗位填默认NPC；数据库只保存0，完整恢复没有将其转换为对应NPC身份。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `canteenaction.lua` | 撤岗回调 |
| `account_db.py` | career恢复 |
| `dormdata.lua` | NPC岗位初始化 |

## A197｜食堂委托把分钟当秒，人员过早释放并恢复疲劳

### 出现什么现象

长时间委托中的角色过早恢复疲劳，任务到期后占用状态也与客户端不同。

### 初步定位

疲劳恢复把以分钟保存的 duration 当作秒使用；领奖检查和客户端则正确乘60，导致同一实例有两套到期时间。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `account_db.py` | 委托占用与疲劳恢复 |
| `backhome_service.py` | 领奖时间检查 |
| `canteenentrustdata.lua` | 到期计算 |

## A198｜岗位派遣缺少角色资格与排他检查，同一角色可重复占用

### 出现什么现象

未拥有角色、未知ID、无效岗位和同本体重复派遣都能保存成功。

### 初步定位

岗位与单批派遣只检查已有后宅行的锁定状态，缺行不拒绝，也未检查持有、合法岗位及本体在岗位和委托间的排他占用。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | 单人、批量派遣与岗位校验 |

## A199｜安排岗位被误计为完成委托，重试还能重复增加成就

### 出现什么现象

安排食堂岗位也会增加接取、完成委托的任务和成就次数。

### 初步定位

岗位变更、委托刷新和解锁复用 commission 事件，消费者把它当成真实委托行为；原岗位不变重试也会再次计数。

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | DORM_ACTION生产 |
| `task_listener.py` | 条件2007 |
| `achievement_service.py` | 80004—80007 |
