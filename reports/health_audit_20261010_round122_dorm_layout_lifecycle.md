# 第122轮｜房间布局、模板与入住恢复

扫描日期：2026-10-10。问题编号：A222、A223、A224、A225、A226。

## A222｜房间布局被服务端裁减，仍按完整布局返回成功

### 出现什么现象

布局保存只接受部分家具，却仍回复完整成功，界面保留原编辑结果。

### 初步定位

数据库按库存裁剪后保存，服务和回复未回传实际布局，也没有58001、58003；客户端成功后使用原编辑缓存。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `account_db.py` | 布局裁剪与保存 |
| `backhome_service.py` | 布局结果 |
| `operations.py` | 58011回复 |

## A223｜房间余额不足仍能解锁，重复解锁又扣费并清成长

### 出现什么现象

房间资金不足也能解锁，重复解锁还会再次扣费、发初始家具并清成长。

### 初步定位

余额采用 max(0,cur−cost)，没有不足拒绝和已有房间检查；INSERT OR REPLACE重建房间成长，每次都添加初始物件。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `account_db.py` | 房间解锁与初始化 |

## A224｜读取家具模板失败时，以空布局覆盖原模板并返回成功

### 出现什么现象

保存继承房间布局的模板时，读取失败会把原模板覆盖为空且返回成功。

### 初步定位

继承查询和JSON解析异常被直接忽略，随后空布局进入模板替换；异常没有传到Core，无法触发回滚。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | 模板继承查询 |
| `account_db.py` | 模板替换 |

## A225｜公共大厅人员名单保存不完整，清空后重登又出现旧角色

### 出现什么现象

撤下大厅角色后，重登又出现旧人；清空名单也不会清库。

### 初步定位

客户端提交的是完整剩余名单，数据库只逐个插入请求角色，没有删除目标大厅里缺席的旧人；空列表则直接跳过。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | 公共大厅部署 |
| `account_db.py` | 大厅在场名单 |

## A226｜私人房间召回删掉房间归属，大厅里的角色却没撤走

### 出现什么现象

召回私人宿舍会删掉永久房间归属，却没有把角色移出公共大厅。

### 初步定位

客户端意图是回自己宿舍，数据库实现却删除目标私人房间居民行；也没有统一转换形态和本体身份。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `account_db.py` | 私人召回 |
| `backhome_service.py` | 召回入口 |
| `dormaction.lua` | 召回回调 |
