# 第120轮｜委托批量终态、人员释放与食堂设施资格

扫描日期：2026-10-10。问题编号：A209、A210、A211、A212、A213、A214、A215。

## A209｜委托领奖后未通知人员归还，在线入住状态不同步

### 出现什么现象

委托领取后，在线角色没有返回大厅。

### 初步定位

派遣成功会把本体移出大厅，领取回调依赖 fatigue_list 逐个归还；58019却把该列表固定为空，持久入住列表与在线状态分离。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `operations.py` | 58019疲劳列表 |
| `canteenentrustdata.lua` | 派遣 |
| `canteenaction.lua` | 领取归还 |

## A210｜食堂委托派遣与领奖均未扣除配置疲劳成本

### 出现什么现象

派遣委托和领取奖励都不消耗配置要求的疲劳。

### 初步定位

两个阶段均没有读取任务cost并检查或扣减人员疲劳，成本只参与客户端选择；cost120的合法任务结束后疲劳仍为120。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | 委托派遣与领奖 |

## A211｜刷新或重复解锁委托会清掉进行中任务，同日还能多次刷新

### 出现什么现象

进行中的委托可被刷新或重复解锁覆盖，同日也能多次刷新。

### 初步定位

刷新和解锁直接替换槽位，没有检查生命周期、已开放状态及日限额，会清空原人员和开始时间。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | 委托刷新、解锁与 refresh_times |

## A212｜食堂设施未检查升级条件，满级仍成功并让客户端再升一级

### 出现什么现象

未满足烹饪条件仍能升级设施；满级重复请求还让在线等级继续增加。

### 初步定位

服务端只检查金币和硬编码最高3，未知设施也能新建；满级返回成功但不带最终等级，客户端成功回调直接加1。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | 设施升级 |
| `operations.py` | 升级回复 |
| `canteendata.lua` | FurLevelUpCallBack |

## A213｜食堂设施容量未接入计算，存储上限与客户端不一致

### 出现什么现象

食堂收入上限不随设施等级变化。

### 初步定位

制作和领取固定使用14000上限，没有读取设施存储加成；当前配置全一级容量8000、全三级16000，两端因此不一致。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `account_db.py` | MAX_EARNINGS_CAP |
| `backhome_service.py` | 收入领取上限 |
| `dormskilldata.lua` | CalInComeStorageMaxNum |

## A214｜食堂计时广播参数不匹配，自动制作被跳过

### 出现什么现象

定时器触发后食堂没有自动制作，打开详情却会补算。

### 初步定位

TIME_TICK订阅器传入 now_ts，但实际制作方法只接受self和uid；参数异常被捕获，仅留下debug记录。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | TIME_TICK订阅 |
| `account_db.py` | _calculate_canteen_dishes |
| `lazy_timer.py` | TIME_TICK |

## A215｜食堂未检查菜谱解锁条件，未知菜品也能上架赚钱

### 出现什么现象

未解锁菜品或未知菜品也能上架并产生收益。

### 初步定位

上架只检查ID和数量非零，未核有效菜谱、解锁条件和设施等级；制作对未知ID还提供默认耗时与售价。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | send_sign_food |
| `account_db.py` | 菜谱默认值 |
| `canteentools.lua` | CheckFoodUnLock |
