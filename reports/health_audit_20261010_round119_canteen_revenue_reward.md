# 第119轮｜食堂营业、食材与委托领奖

扫描日期：2026-10-10。问题编号：A200、A201、A202、A203、A204、A205、A206、A207、A208。

## A200｜食堂售菜未正确扣除食材，扣料失败也继续获得收入

### 出现什么现象

食堂自动和手动售卖都能产生收入，却不消耗食材。

### 初步定位

自动制作未处理 ingredient_list；手动调用扣料后忽略失败，而统一扣除接口本身没有type16食材分支。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `account_db.py` | 自动制作 |
| `backhome_service.py` | 手动结算 |
| `inventory_service.py` | cost_item |

## A201｜食堂 NPC 不产收益，手动营业期间仍执行自动售卖

### 出现什么现象

三名合法NPC无法自动营业，手动营业期间却仍会自动卖菜。

### 初步定位

自动制作只接受有普通后宅角色行的岗位人员，忽略独立NPC；同时未检查营业模式和三岗位是否齐备。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `account_db.py` | _calculate_canteen_dishes |
| `canteentools.lua` | 营业资格 |
| `canteendata.lua` | 模式状态 |

## A202｜食堂重新上架未清旧销量和收入，在线与重登状态不同

### 出现什么现象

新一批上架沿用上一批已售数量，下架后长期菜品次数又归零。

### 初步定位

重上架更新 sell_num 却保留旧 sold_num 和收益，下架则删除整行；恢复又把该行批次销量作为长期完成数。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | 上架与下架 |
| `account_db.py` | 菜品完成次数恢复 |

## A203｜食堂手动收益写入错误货币，客户端也未收到资产刷新

### 出现什么现象

手动营业收益进入错误货币，在线也没有对应资产更新。

### 初步定位

手动结算实际增加ID31且未标记 touched_items；客户端食堂货币和正常自动领取使用ID39。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | 手动收益与自动领取 |
| `dormconst.lua` | DORM_CURRENCY_ID |

## A204｜食堂销量已保存但待领取收益缺失，领取结果为零

### 出现什么现象

缺少食堂元数据时，菜已售出却领不到收入，累计收入显示还会突然变化。

### 初步定位

制作照常推进销量，但待领取收益只UPDATE不存在的meta行；恢复用固定1847982作显示默认，建立meta后又显示零。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `account_db.py` | 制作、settle_canteen_earnings与meta恢复 |

## A205｜食堂手动领奖调用错误模块，成功回调无法完成

### 出现什么现象

手动营业成功回调可能在奖励处理处中断。

### 初步定位

回调调用 CanteenFoodData.GetManualAward，但当前源码将该方法定义在独立 CanteenManualData；后续成功通知排在这个调用之后。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `canteenaction.lua` | 手动奖励回调 |
| `canteenmanualdata.lua` | GetManualAward |
| `datainclude.lua` | 对象加载 |

## A206｜委托领奖后没有结束旧领取资格，同一槽位可再次发奖

### 出现什么现象

委托领奖刷新出新任务后，立即重复请求还会再次发奖。

### 初步定位

领取只在开始时间和时长都非零时核对到期，新槽开始时间为零便跳过检查；刷新槽位没有形成已消费实例的终态保护。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | 委托领奖、实例刷新与开始时间检查 |

## A207｜委托食材已到账，客户端背包没有刷新

### 出现什么现象

委托发出的食材已入后宅表，但材料镜像和在线资产包没有同步。

### 初步定位

510前缀食材直接调用 add_ingredient，没有经过统一发奖或标记 touched_items；其他奖励走正常链路，造成部分资产遗漏。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `backhome_service.py` | 委托奖励 |
| `account_db.py` | add_ingredient |
| `generator.py` | 17023.back_home_list |

## A208｜后宅工作状态切换未推进计时，疲劳恢复重复累计

### 出现什么现象

从工作切回闲置后，工作期间的时间也被用于恢复疲劳。

### 初步定位

恢复按当前状态解释整段 now−update_ts，忙碌分支直接跳过且不推进游标；岗位变更没有先结算旧状态。

### 相关文件与入口

| 文件 | 定位入口 |
| --- | --- |
| `account_db.py` | 疲劳恢复游标 |
| `backhome_service.py` | 岗位切换 |
